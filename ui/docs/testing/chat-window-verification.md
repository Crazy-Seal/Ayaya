# 独立聊天窗口验证

运行 `npm.cmd run test:unit` 验证消息展示、审批、窗口尺寸修正、截图恢复和前端配置读写。
运行 `npm.cmd run test:desktop` 构建后启动真实 Electron、preload 和生产页面。

桌面验证脚本创建系统临时目录，并通过 `AYAYA_UI_DATA_DIR` 隔离模型和前端配置；
主进程的后端请求全部由内存响应和事件流替代，不启动 Python、不连接生产服务。
此验证覆盖窗口与前端行为，不代表真实模型服务或屏幕操作接口已完成端到端验证。

桌面验证包括：

- 聊天与 Live2D 分离；聊天移动、缩放和置顶不改变角色窗口。
- 关闭转最小化；最小化保留草稿、粘贴和拖入的附件，并继续接收消息。
- 单条共享订阅；表情跨窗口转发；同一审批事件只触发一次提醒。
- 审批保持最小化；外部处理和本地提交后的后端确认均清除对应提醒。
- 截图隐藏角色并保留聊天最小化；显示器变化不把最小化窗口弹出。
- 模态框键盘焦点约束；设置底部日志和退出按钮等大且可见。
- 所有设置分类、日志、审批、退出确认和图片预览页面加载与截图。
- 配置保留截图选项、普通窗口位置尺寸和置顶，不保存最小化。
- 第二个 Electron 进程使用上次测试配置验证重启恢复，并确认窗口正常显示。
- 重启断言比较启动前的配置；显示缩放允许系统报告一像素取整差，但不把差值写回配置。
- 设置取消退出不提交请求；确认退出调用现有入口；应用退出允许释放聊天窗口。

截图和结果保存在 `ui/.test-dist/desktop-smoke/`，不会进入版本控制。
在 Windows 下运行真实鼠标验证：

```powershell
node node_modules/electron/cli.js scripts/verify-desktop-windows.mjs --composer-check
node node_modules/electron/cli.js scripts/verify-desktop-windows.mjs --native-drag --dev
```

`--dev` 在独立的 5174 端口启动 Vite，所有窗口仍使用临时配置与模拟后端。
第二条命令通过独立 PowerShell 进程调用 Windows 鼠标接口，实际按住四条边和标题栏，
采样系统屏幕而非仅调用 `setBounds`；断言窗口确实移动、对边坐标稳定、没有额外白色边带，
并检测角色重叠拖动时屏幕左侧的非背景像素。测试会暂时覆盖屏幕工作区并操作鼠标，
请保持测试窗口在前台；测试结束后恢复鼠标位置并销毁测试窗口。
`--left-only` 连续执行五次左边缩放，用于复查间歇性绘制问题。

聊天窗口在 Windows 上使用透明合成并由页面绘制深色背景，标题栏和八个缩放方向
采用页面鼠标捕获与主进程系统坐标计算。移到角色区域时保持角色窗口穿透，
松开、失焦、最小化或页面卸载后停止采样并恢复正常命中检测。
本地差异测试中，不透明聊天窗口曾在五次左边缩放中多次出现白条；
改用透明合成后连续五次未出现。角色位置、聊天订阅和消息协议不参与这一调整。
Electron 的透明窗口原生缩放存在限制，因此使用应用绘制的边缘区域保留缩放能力；
可对照[透明窗口说明](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles#limitations)。

输入区验证同时检查单行和多行草稿的三个控件等高，以及快捷键提示已移除。
原生画面结果保存在 `ui/.test-dist/native-drag/`。有限帧采样不能证明所有机器上的
间歇性残影都已消失；本次修改前捕获过左边缩放时右边约 12 物理像素的白条，
屏幕左侧残影尚未稳定复现。应在用户原有的开发模式和显卡环境中继续人工验收。

实际多显示器拔插及操作系统减少动画选项仍可按上述场景人工复验。

后续日志白边与聊天圆角修正：

- 聊天与日志共用 `src/ui/window-gestures.ts`、`electron/window-gesture.ts` 和共享边缘样式。
- 两个原生窗口使用透明背景，页面透明底色中绘制统一 14px 圆角与深色渐变，圆角之外不填充方形底板。
- IPC 从发送者取得窗口，只操作已登记的当前窗口；失焦、最小化、关闭或卸载都释放对应采样。
- 按用户要求，这轮不运行真实鼠标拖动或桌面截图脚本；构建与现有单元测试通过，桌面效果由用户验收。
- 人工重点检查日志四边和四角缩放、拖入角色区域、最小化恢复、关闭后重新打开，以及聊天上下四角是否露出桌面。

退出等待期间的操作保护：

- 确认退出后，设置窗口同步进入“正在退出…”；主进程先关闭业务 IPC 门禁，再停止订阅、后端和日志。
- 聊天、设置、日志及图片预览共用退出提示、控件禁用和事件拦截；角色窗口停止交互并保持鼠标穿透。
- 业务与日志 IPC 都通过统一门禁，退出期间拒绝新的查询或写操作，忽略按钮事件和重复退出。
- 仅保留退出状态查询，迟加载的页面也能锁定；迟到的普通状态不解除已生效的锁定。
- 已开始的操作不回滚，资源继续按现有退出流程清理；退出等待期间不会重新开放按钮。
- 单元回归模拟后端持续等待、按钮被异步回调重新启用、通知与首次查询交错和页面卸载。
- 本轮不运行桌面拖动或截图脚本；人工确认退出后可尝试发送、设置保存、模型切换和日志清空，应全部不再生效。

提交前审查与补充回归：

- Standards 轴纠正 Live2D 资源参数的注释，并移除聊天审批遮罩与动作区重复的共享样式。
- Spec 轴修复断线期间完成回答后，经完整历史恢复却遗漏未读提醒的问题；首次旧历史和重复恢复不提醒，失败查询不提前记录回复编号。
- Spec 轴修复模型切换后旧选图或图片转换迟到结果写入新草稿的问题；清空时使旧结果失效，首次模型初始化保留启动等待期间的草稿。
- 新增 5 项回归覆盖历史恢复提醒、终态历史与失败查询、迟到选图、迟到图片转换和并发附件上限；共 190 项单元测试通过，完整构建通过。
- 本轮按用户要求不运行真实鼠标或桌面截图脚本，视觉与原生绘制仍由用户人工验收。

开发命令的退出行为：

- `npm run dev` 使用 `run-p --race` 同时管理 Vite 与 Electron；Electron 正常完成退出清理后，结束同次开发命令启动的 Vite 进程树，终端返回提示符。
- 子任务异常退出仍保留失败退出码并终止其余子任务；不按进程名称清理，不影响其他项目的开发服务。
- 使用临时 npm 项目与模拟桌面进程验证：旧命令在桌面进程正常退出后仍等待；加入 `--race` 后正常退出返回 0、异常退出返回 1，两个场景都结束模拟开发服务。测试未启动 Electron 或后端，未访问生产数据。
- 聊天窗口的关闭请求仍转为最小化，设置与日志的关闭按钮仍只关闭对应窗口；退出整个应用应使用设置页“退出”并确认。
